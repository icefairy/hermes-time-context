Hermes Plugin 0 依赖 缓存代价 ≈ 0 Apache-2.0

让 Hermes 的模型知道
现在几点，以及你上次说话是几小时前

多轮对话里消息本身不带时间。你隔了一天再接着说，模型却以为还是“刚才”。 hermes-time-context 在发给模型的最后一条用户消息前，加一行现实时间与轮次间隔—— 历史前缀逐字节不变，上游缓存照常命中。

★ 在 GitHub 上查看 安装（2 步） 缓存代价说明

01问题长什么样

没有时间信息时，模型会把跨越一整天的两句话当成连续对话：

你 · 10月1日 09:00
帮我看下这个脚本为什么报错
AI
从报错看，可能是环境变量没设置。
你 · 10月2日 15:30
改好了，但还有个小问题
AI
好的，基于刚才的报错信息…… ← 它以为还是“刚才”

装上插件之后，模型看到的是：

【当前时间】2026-10-02 15:30 周五（Asia/Shanghai）｜距上一轮：1 天 6 小时
改好了，但还有个小问题

02特性

🕐

现实时间

北京时间或任意 IANA 时区，前缀模板与 strftime 格式都可自定义。

⏱️

间隔感知

超过阈值的断档自动标注「距上一轮：1 天 6 小时」，阈值以下不啰嗦。

🧠

缓存友好

只改最后一条用户消息。历史前缀字节不变，上游前缀缓存继续命中。

🔒

零侵入

不碰系统提示词、不改持久化历史、不动 assistant 与 tool 消息。

📊

自带观测

/time-context stats 统计命中率，用数据证明缓存没被伤到。

🪶

纯标准库

零第三方依赖；zoneinfo 缺失时自动回退 UTC+8。

03为什么不做在网关层？

第一反应往往是“在 API 网关里统一加个时间戳不就完了”。这行不通——原因不在于能不能加， 而在于网关根本不知道正确的值。

网关层插件层（本方案）
知道“上次交互是什么时候”✗ 只知道本次请求时间✓ 按 session 记录真实间隔
区分“用户说的话”与“工具返回”✗ 很多协议里都是 role=user✓ 能，结构化判断
会污染历史消息吗△ 若逐条加就会✓ 只改最后一条
耦合 Hermes 私有会话库△ 只能解析库格式✓ 用框架公开扩展面

还有个细节：Hermes 的消息在数据库里其实带 timestamp， 但它在 PERSISTENCE_ONLY_MESSAGE_FIELDS 里，发往模型前会被剥掉。 网关侧要拿到它，只能去解析 Hermes 私有的会话库格式——耦合度一下就上去了。

这也正是 Hermes 官方把注入点定在「当前轮 user 消息」而非系统提示词的同一个理由： system prompt 保持字节稳定，缓存才成立。

04缓存代价 ≈ 0

上游前缀缓存按 token 逐字节比对前缀。任何位置变了，该位置之后全部失效。

注入位置结果
系统提示词开头（“Current time: …”）💀 每次请求前缀全变，命中率归零
每条 user 消息前💀 历史前缀作废，等于每轮重建
role=user 的工具结果上💀 污染工具输出语义 + 破坏断点
只加最后一条 user 消息✅ 历史逐字节不变，只多几十 token prefill
易忽略的细节：Anthropic 系的缓存断点（cache_control）最多 4 个， Hermes 默认放在「system 静态前缀 / system 末尾 / 最后 2~3 条消息」。 如果给每条 user 消息都加时间戳，这些断点会被不断刷新，效果等同于每轮冷启动。 所以 only_last_user_message 默认开启，且建议保持开启。

05安装（2 步）

  1. 放进插件目录 
    # 克隆后复制到 Hermes 插件目录
git clone https://github.com/icefairy/hermes-time-context.git
cp -r hermes-time-context ~/.hermes/plugins/time-context
  2. 在 $HERMES_HOME/config.yaml 的 plugins.enabled 里加一行 
    plugins:
  enabled:
    - time-context
    # ... 你已有的其他插件
    然后重启 Hermes 进程（网关 supervisorctl restart <worker>，CLI 退出重进）。
注意：Hermes 的插件是 opt-in 的——只把目录放进去不会生效， 必须在 plugins.enabled 里显式列出，否则日志会出现 not enabled in config。目录名必须叫 time-context，与 plugin.yaml 的 name 一致。

06配置

写在 config.yaml → plugins.entries.time-context.settings。所有键都在 plugin.yaml 的 config_schema 里声明过，Desktop 的插件设置页会渲染成表单。

plugins:
  entries:
    time-context:
      settings:
        tz: Asia/Shanghai
        gap_threshold_minutes: 30
        min_gap_tokens_alert: 0.3
键默认说明
enabledtrue总开关
format【当前时间】{datetime} {weekday}（{tz}）模板；可用 {datetime} {date} {time} {weekday} {tz}
date_format%Y-%m-%d %H:%Mstrftime 格式
tzAsia/ShanghaiIANA 时区；zoneinfo 不可用时回退 UTC+8
gap_enabledtrue是否追加「距上一轮」
gap_threshold_minutes30低于该间隔不追加（避免每轮都提示“刚刚”）
inject_on_first_turntrue新会话首轮是否也注入
only_last_user_messagetrue保持开启，关闭会让历史缓存作废
min_gap_tokens_alert0.0>0 时，未命中比例超阈值的请求写一条日志（0 = 关闭）

07怎么用

安装后在会话里直接用斜杠命令：

/time-context status     # 当前配置、已记录的会话数
/time-context preview    # 试算三种间隔下的前缀长什么样
/time-context stats      # 本进程缓存命中统计
/time-context test 90    # 按“隔 90 分钟”试算一次

stats 的输出大致是：

time-context 缓存观测（本进程累计）
  请求数：42
  prompt tokens：1,284,930
  命中缓存 tokens：1,201,447（93.5%）
  未命中偏高告警次数：0

跑几轮后这个数字应稳定在 90% 以上（取决于历史长度与上游）。若明显下降，先检查 only_last_user_message 有没有被关掉。

08它是怎么工作的

全部只用 Hermes 的公开扩展面，没有任何 hack：

messages 组装Hermes
prompt-cache 装饰（放置 cache_control 断点）Hermes
sanitize → api_kwargsHermes
llm_request 中间件 · 改写最后一条 user 消息本插件
pre_api_request hookHermes
发往 provider上游
post_api_request hook · 统计缓存桶本插件

中间件在缓存装饰之后执行，所以 cache_control 已经就位， 插件只管替换字符串，不新增内容块（不占新的断点位）。 间隔记录写在插件自己的 state 里（按 session_id），进程重启后仍然有效。

防误伤：role=user 但内容全是 tool_result 块（Claude 工具结果）的轮次直接跳过； 字符串与内容块数组两种形态都保持原有结构；任何异常静默降级，绝不影响对话。

09生态背景：Mizar · 璇玑 · Hermes

hermes-time-context 并不是孤立的项目，它诞生于一套面向多 agent 协同的自研体系， 命名皆取北斗七星：Mizar（开阳） 是第六星，璇玑（Xuanji） 是北斗一二星（枢纽之意）。

Mizar（开阳）

GitHub · 极简、零依赖、单文件、可自举 的 AI Agent 框架。

  • 单二进制：~20-30MB，无运行时依赖，无需 npm / Python / Docker
  • 插件即脚本：.ts 内嵌 esbuild 编译、.js 直跑 goja，热重载无需重启
  • 技能即 Markdown：兼容 Anthropic / Hermes 第三方技能生态
  • 工具即 MCP：接入任意 MCP 服务器
  • 可自举：Agent 自行编写插件并扩展自身能力

Hermes 是「多通道集成终端」，Mizar 是「独立 agent 本体」；两者共享同一批 SKILL.md 技能，可无缝切换或组合使用。

璇玑（Xuanji）

GitHub · Go 单二进制 + SQLite 的轻量 AI 协议网关，OpenAI / Anthropic 双入口。

  • 多上游汇聚：vLLM、硅基流动、商汤、DeepSeek 中转、OpenRouter、Ollama、MiMo TTS …… 统一一个入口
  • 自动分流：按计费层级（免费 / 包月 / 按量）+ 权重 + 优惠时段 + 延迟智能路由
  • 故障切换 + 熔断恢复：按上游独立健康探测，2xx / 全部 4xx 算“在线”，仅 5xx / 超时判死；客户端断连不拉黑
  • 协议归一：对上游私有扩展做归一化（如 DeepSeek 思考等级映射、reasoning_content 缓存回传）
  • 配置热重载：管理页 CRUD → SQLite → reload，在途请求用旧配置、新请求用新

三者关系

# 请求路径（简化）
用户 ──► Hermes (MCP / 插件生态) ──► 璇玑网关 ──► 各上游模型
            │
            └──► Mizar (独立 Agent / 技能复用)
层次项目角色
入口Hermes / Mizar用户交互、插件 / 技能扩展
路由璇玑网关多上游汇聚、自动分流、协议归一
增强hermes-time-context单点修补——让跨天会话的时间语义不被丢

插件把时间戳加在 user 消息上，请求经璇玑网关转发到上游，命中缓存并正确携带时间语义。 三者配合才能让「时间感知」这条信息稳定抵达最终模型。

10已知边界

只影响发往模型的内容——终端里显示的仍是你的原文（这是设计，不是 bug）。 上下文压缩后的摘要轮同样会注入时间，这是期望行为。 时间格式使用本机时区的 IANA 名；Windows 上若没有 tzdata，会静默回退到 UTC+8。
